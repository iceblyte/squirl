SquirlInterface language · v0.1

一张安静的台账。
信息靠排版分层，动作只留一个。

这是 Squirl 的界面设计语言与结构草图，用于在进入高保真原型前确认方向。 整体取 magpie 的密度与克制、ElegantClipboard 的面板与描边，再压掉所有装饰： 没有渐变、没有彩色块面、没有图标墙。路径和命令是主角，所以它们用等宽字体完整露出。

magpie — 行式列表 / 细描边 / 黑白动作色 ElegantClipboard — 侧栏导航 / 分区卡片 / 墨色选中态 Linear · Raycast — 键盘优先 / 密度 / 无标题栏噪音 JetBrains Toolbox — 项目清单的信息取舍
01

五条设计原则

所有页面决策回落到这五条；冲突时按序号优先。

01 / SURFACE内容优先，装饰归零

不用渐变、不用彩色卡片底色、不用插画。层级只靠字号、字重、留白和 1px 描边区分。

02 / COLOR只有一个强调色

橡果褐只表示「活着 / 正在发生」。其余全部中性灰。颜色是状态，不是装饰。

03 / DENSITY密度换效率

13px 基准字号、20px 行高，一屏能放下 12 个项目卡片。这是工具，不是展示页。

04 / PATH路径是一等公民

路径、命令、cwd 一律等宽字体、可完整读取、可一键复制。截断只发生在尾部，hover 出全文。

05 / STATE状态永远可见

六种运行状态用「圆点 + 微标签」常驻呈现，不用弹窗打断操作，不用进度条动画抢注意力。

02

视觉方向 · 三选一

三个方向共用同一套布局与字体，只差「强调色」这一件事。推荐 A。

A · 纸感台账

暖中性灰 + 橡果褐

推荐
squirl

画布带一点纸的暖度，纯白卡片浮在上面。橡果褐呼应松鼠存坚果的命名，也是唯一有温度的颜色——运行中、焦点环、主按钮 hover 都用它。

适合：想让工具「有性格但不吵」。长时间盯屏不累眼。

B · 纯灰阶

完全无彩，最接近 magpie

squirl
D:\Code\AICreate\ZCode\squirl
▶ Run dev

所有动作色都是近黑。运行中状态靠圆点的「呼吸动画」而不是颜色表达。最克制、最耐看，但六个状态只能靠灰阶深浅区分，辨识度弱一档。

适合：追求极致冷静；愿意用动效替代颜色做状态区分。

C · 墨青

冷中性 + 深墨绿，接近 ElegantClipboard

squirl
D:\Code\AICreate\ZCode\squirl
▶ Run dev

冷灰画布 + 墨青强调，最「工程师工具」的一版。和终端、代码编辑器同色温，气质统一，但和市面上大量深青色的开发者工具较难区分。

适合：希望和终端环境视觉一致；不在意品牌辨识度。

08

动效

只有三种时长。所有动效都是「反馈」，没有一个是「表演」。

120mshover 变色、按钮按下、图标旋转
180ms下拉展开、卡片 hover 抬升、toast 进出
240ms对话框淡入、发现区折叠、日志坞升降
cubic-bezier(.2,.8,.2,1)统一缓动，全部 ease-out 手感

唯一允许的循环动画是 running 状态的呼吸环（1.8s）。不做骨架屏流光、不做加载转圈——扫描用顶部 2px 进度条。

10

待你确认的四件事

这四点会直接影响下一步高保真原型的产出方式，其余细节我可以自行决策。

Q1
视觉方向选 A / B / C？

我推荐 A（纸感台账 + 橡果褐）。如果更想要 magpie 那种完全无彩的冷静感，选 B；想贴近终端色温选 C。

Q2
界面文案用英文还是中文？

需求文档 F8 明确「UI 文案英文 + react-i18next」。但评审阶段中文更容易读。建议：原型按英文出，关键术语旁注中文。

Q3
主界面两分区是「上下堆叠」还是「左右分栏」？

需求附录 A #10 定的是上下两分区，我按此设计。但「本次发现」条目多时会把已登记区挤到需要滚动；也可以改成右侧可折叠抽屉。要不要我在草图里两种都画一版对比？

Q4
扩展功能（P1/P2）要不要现在就出原型？

招牌功能里「README × 配置双栏快填台」和「全局 CLI 词典 + 参数模板」的界面形态最不确定，值得先出概念稿验证；其余（托盘、端口雷达）可以等 MVP 定稿后再补。
