招牌功能的界面形态

MVP 不做的部分。这里只验证界面形态是否成立，不涉及实现细节——形态定下来之后，优先级排序才有意义。

六个概念：托盘面板、全局命令、多会话日志、README × 配置双栏快填台、CLI 词典与参数模板、端口雷达。

P1

托盘面板

常驻但不打扰。托盘点开就是「最近用过的 5 个项目」，一个按钮直接跑。

只有 5 条

托盘不是第二个主窗口。它只放最近用过的 5 个，找更多就打开主窗口。

状态优先

运行中的永远排在最前，且右侧按钮直接变成「停止」——这是托盘唯一的高频动作。

默认关闭

关窗=隐藏还是退出，需要一个开关。默认「关窗即退出」保持 MVP 语义不变。

全局命令

和项目命令同一个数据实体，只是不绑根目录、工作目录默认主目录。覆盖「忘了有哪些 CLI、忘了长参数怎么拼」。

和项目命令同一个表

只多一个 type: global 字段，不绑 project_id。搜索、运行、保存全部复用。

「用途」是一等字段

这个功能的价值一半在「这条命令是干什么的」。没写用途的命令在列表里会显得单薄。

不抢主界面

全局命令单独一页，从顶栏入口进，不占主界面的两个分区。

标签在日志坞顶部

不另开窗口。切标签 = 切 run_id，日志缓冲各自独立。

「全部停止」放命令列表上方

它是危险动作，放在能看见所有命令的位置，且需要二次确认。

关标签 ≠ 停进程

关标签只是不再看日志，进程继续跑。这个语义要在标签上明确（关闭时提示）。

左栏是只读渲染

README 用 GFM 渲染，代码块右上角一个「设为启动命令」，把这块代码直接变成命令。

右栏是结构化表单

从 .env / .yml / .toml 解析出键值，写成表单。写回时保格式原子重写，不重排文件。

联动是灵魂

表单聚焦某个变量时，左栏自动滚到 README 里提到它的那一段。这才叫「不用来回切」。

P2

参数模板填空

命令里写 {{param}}，运行时弹一张小卡片填空。长参数组合不用再背。

dsh deploydsh deploy {{service}} --env={{env}}
pipi --model {{model}} --profile work
codexcodex --sandbox {{mode}} --cwd {{dir}}
运行 dsh deploy 2 个参数
预览
dsh deploy order-api --env=prod
serviceorder-api
envprod
可选值：dev · staging · prod
参数有两种

自由输入（{{service}}）和枚举选择（{{env:dev|prod}}）。枚举直接给下拉，减少打错。

实时预览

顶部一行把填好的值合成完整命令，用户在按运行前就知道会发生什么。

不存值

填过的值只在这一次运行里有效，不回写命令原文——避免模板被悄悄改坏。

P3

端口雷达

启动前预检冲突，运行中把端口徽章挂在卡片上，点一下直接开浏览器。

徽章只在有意义时出现

没有端口信息的项目不加徽章，避免每个卡片都挂一排装饰。

冲突要说清是谁占的

「:8080 被占用」后面必须能展开看到占用的 PID 与进程名，并提供终止入口。

点徽章开浏览器

运行中的端口徽章可点击，直接打开 http://localhost:5173。

关于优先级：这六项里，托盘面板和全局命令成本最低、留存价值最高，建议 P1 先做； 双栏快填台是差异化最强但工作量也最大的一项（涉及文件解析与保格式写回），适合在 MVP 稳定后再启动； 端口雷达依赖系统 API，跨平台差异大，放 P3 合理。
