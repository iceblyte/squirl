## Squirl 是什么

**Squirl**（松鼠的变体拼法）——一只替你记住坚果埋在哪的松鼠。

它是一个**本地项目台账与一键启动中枢**：把散落在多个根目录下的项目登记成一张可搜索的清单，记住每个项目该怎么跑，点一下就启动——默认在你惯用的终端里执行，也可切换为应用内运行并实时查看日志；由应用内启动的进程，在退出时全部收回。

它**不是**：文件搜索器、环境管理器、IDE、终端替代品、重型 Git 客户端。

## 快速上手

1. **添加根目录**：主页 → 「添加根目录」→ 选择一个存放项目的文件夹（可多个）。Squirl 立即扫描（默认只列一级子文件夹）。
2. **登记项目**：在「本次发现」区点「登记」；或直接把文件夹拖进窗口，或用「手动注册」选择任意位置的文件夹。
3. **保存命令**：进入项目详情 → 输入命令名与命令行原文（如 `npm run dev`）→ 点「保存」。填了命令不想保存也可以直接点「运行」（临时执行，应用内运行结束后会问你一次要不要保存）。
4. **一键启动**：
   - **外部终端（默认）**：在命令的工作目录按「模拟器 × Shell」唤起终端执行，命令跑完后窗口保持打开，你自己关闭。
   - **应用内运行**：设置页把默认模式切为「应用内运行」，或在项目级覆盖。输出实时显示在日志面板（ANSI 颜色保留，30ms 分批，最多保留 5000 行 / 2MB）。
5. **停止**：应用内运行中的命令点「停止」——整棵进程树（含 npm 派生的孙进程）全部回收；外部终端的进程归终端所有，请自行关闭窗口。

## 数据与安全

- 所有数据（SQLite、备份、日志）只存在平台标准数据目录（Windows `%APPDATA%\app.squirl.desktop`），**绝不写入被管理的项目目录**。
- 数据库自动备份：滚动保留最近 3 份（迁移前快照独立 2 份）；启动检测到损坏自动以最近备份恢复并提示。
- **命令以明文存储**，可能包含 token / API key——这是已接受的安全事实，v1 不加密。

## 已知限制（诚实清单）

- **异常崩溃时的进程回收兜底**（正常退出 / 手动停止不受影响）：
  - Windows：Job Object 由内核保证整树回收；
  - Linux：`PR_SET_PDEATHSIG` 只保证直接子进程，**孙进程可能遗留**；
  - macOS：无等价机制，**可能遗留孤儿进程**。
  → 两条兜底路径与「正常退出回收」不得混同；异常崩溃后请用任务管理器检查。
- **应用内模式无 stdin**：不支持交互式命令（Y/N 确认、密码输入）。疑似等待输入时（30s 无输出）会提示，可强制停止。阈值 30s 为初值，长静默构建（大型依赖安装、Rust 全量构建）可能误报——只提示，不干预。
- **外部终端命令含字面 `exit`**：cmd 的 `/k` 拦不住 `exit` 内建命令，窗口会关闭（bash/pwsh 有子壳/脚本保护）。这是 cmd 语义限制。
- **命令执行完窗口保持打开**是外部模式的设计：防止报错闪退看不到原因。
- **无代码签名**：首次运行可能触发 SmartScreen 提示（发行版待签名预算）。
- macOS / Linux：产物照发，**未经实机验证**（macOS osascript 转义、Linux 终端适配仅代码级单测 + CI），宣传口径不写「三端可用」。
- PS 5.1 不支持 `&&` 管道链——设置页选中它时会有警告，相关命令会失败（不代改命令）。

## 排查

「外部模式点了没反应」/「进程残留」两类问题：应用诊断日志在数据目录 `logs/`（rolling），每次启动都有结构化 launch record（实际执行的 program / args / cwd / shell / 模拟器），每次回收都有 reap record。
