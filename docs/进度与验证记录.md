## Spike A 冒烟结论（2026-11-02，Windows 实机）

运行方式：`cargo test --test spike_a -- --ignored --test-threads=1` → **15/15 全绿**（约 57s，含真实终端窗口弹出）。

| 项 | 结果 | 证据 |
|---|---|---|
| A1 WT × pwsh/cmd/GitBash | ✅ | 三组合均命令直传语义保真（result 文件内容精确匹配）；`wt -d <cwd> -- <shell 原参数>` 的 `--` 分隔符实机验证受支持 |
| A2 conhost × pwsh/cmd/GitBash | ✅ | CREATE_NEW_CONSOLE 直启 shell，三组合均保真 |
| A3 空格/引号/`&`/`&&`/中文路径 | ✅ | pwsh 引号+反引号转义串、`a&b` 字面量、`&&` 链、cmd `&` 分隔符、bash 引号含 `&`，全部保真；中文+空格目录三 shell 相对写入全部命中 |
| A3 PS5.1 `&&` | ✅ | `-Command` 形态解析失败 → 非零退出、后段不执行、启动器（应用）不崩 |
| A4 保持打开 | ✅ | pwsh `-NoExit -File`、bash `( cmd ); exec bash`、cmd `/k`（失败命令 `type` 不存在文件）、WT×pwsh（PID 级存活验证）——四路径全部不闪退 |

**实测定版表（写入 adapter.rs 供实现）**：

| 组合 | 保持打开形态 | 说明 |
|---|---|---|
| WT × {pwsh, cmd, GitBash} | `wt -d <cwd> -- <shell 原参数>` | wt.exe 句柄即退；shell 短持 |
| conhost × pwsh | `-NoLogo -NoExit -File <脚本>`（pwsh7 加 `-Login`） | 脚本 = marker + 命令原文，UTF-8 BOM，写数据目录 tmp，启动清扫 |
| conhost × cmd | `/k <原文>`（raw 传递） | 已知限制：命令含字面 `exit` 时 cmd 连 `/k` 一起结束（cmd 内建语义，无法在不二次解析的前提下规避） |
| conhost × GitBash | `-lic "printf marker; ( <原文> ); exec bash"` | 子壳形态：`exit` 只杀子壳 |
| macOS Terminal/iTerm2 × zsh/bash | `do script "<cd && …>"`（tab 即交互 shell） | 代码级实现 + AppleScript 转义单测；**未实机验证（R1）** |
| Linux gnome-terminal/konsole × bash/zsh | `<emu> -- bash -lic "…( <原文> ); exec bash"` | 代码级实现；**未实机验证** |

**转义规则表（quoting.rs 定版）**：
- pwsh/PS5.1：`-Command` 脚本 = `Write-Output '<marker>'; <原文>`（内置模式）；外部 keep-open 走 `-File` 脚本文件（零转义，原文逐字节）。
- cmd：`/c`（内置）`/k`（外部）+ **raw 传递**（`CommandExt::raw_arg` / CreateProcessW 命令行原样拼接）；cmd 不理解 MSVCRT `\"`，绝不可二次引号包装。marker 用 ASCII 变体（控制台代码页安全）。
- bash/zsh：`-lic` 单参数脚本；keep-open 用 `( )` 子壳；marker 用 `printf`。
- **外部唤起必须用 `CreateProcessW` 直启**（不设 `STARTF_USESTDHANDLES`）：std::process::Command 总是传父进程 stdio，`CREATE_NEW_CONSOLE` 的新控制台不接管 stdio，keep-open 交互 shell 会从父 stdin 读到 EOF 立即退出（探针 `tests/probe_keep_open.rs` 实机证据：直启与 conhost.exe 包装均 1.6s/0.4s 内退出）。`lpApplicationName` 不做 PATH 搜索，裸名经 `locate_on_path` 兜底。
- WT 参数含 `;` 需加引号（wt 以 `;` 分隔多命令；适配器经 MSVCRT 引号包装）。

**附带发现**：本机 pwsh profile（starship + PSReadLine）在管道重定向下输出告警文本——正是 F4「profile 噪音与命令输出分离」要处理的真实场景，marker 机制（Write-Output/printf/echo）已验证可区分两段。

## Spike B 验证结论（2026-11-02，Windows 实机）

运行方式：`cargo test --test spike_b -- --ignored --test-threads=1` → **5/5 全绿**（连续复跑稳定）。

| 项 | 结果 | 证据 |
|---|---|---|
| B1 登录 shell + marker 分离 | ✅ | bash + 注入 HOME（临时目录假 `.bash_profile` 输出 FAKE-PROFILE-NOISE）：profile 噪音 < marker < 命令输出，`pipe_marker` 记录 marker 行 seq（seq=5 实测） |
| B2 捕获 + ANSI 透传 + 30ms 分批 | ✅ | pwsh 1000 行 ANSI 输出：批次数远小于行数（30ms 聚合生效）、批次 seq 连续无缺口、`\u{1b}` 原文透传、环形缓冲与批次一致、状态事件链 starting→running→exited(code=0) |
| B3 Job Object 收 `npm run dev` 全链 | ✅ | fixture 三层链（pwsh→npm node→server node→grandchild node）READY 后 `stop_run` → 8s 内 tasklist 全量核对 0 残留；终态 killed、事件不携带退出码（DR-16） |
| B5 崩溃兜底（Windows） | ✅ | `src/bin/job_host.rs` 模拟宿主：挂起-入组-恢复后宿主被 TerminateProcess → 句柄全关 → KILL_ON_JOB_CLOSE 内核收树 → 三层 PID 0 残留 |
| B6 非零退出 → failed | ✅ | `exit 7` → state=failed、事件携带 exit_code=7（AC5 前置） |
| B4 / B5 Unix 侧 | ⏸ 未实机验证 | supervisor 已实现 `process_group(0)` + SIGTERM→3s→SIGKILL + PDEATHSIG；cfg(unix) CI 用例在 Phase 3 接入 ubuntu runner |

**过程中发现并修复的两个生产级缺陷（均已有回归测试）**：
1. **日志聚合器丢消息**：None 分支的 `rx.recv().await.is_none()` 判定会把 recv 到的消息直接丢弃——每次 30ms 间隙 flush 后的第一条消息被吞（marker 行、慢启动命令的首行输出正是这种消息）。修复后新增回归测试 `pipe_does_not_drop_after_idle_gap`。
2. **B5 宿主进程持有测试管道**：job_host 继承测试进程 stderr 且驻留不退，导致 `cargo test | tail` 管道 EOF 永不到来。修复：宿主 stderr 置 null + 测试全路径 taskkill。

**测试卫生约定**（写入用例注释）：Spike B 失败路径必须先 `stop_run`/taskkill 再 panic，防止 npm 树泄漏（首轮调试曾泄漏多个 node 进程，已清理）。

## ADR 列表（无人值守自行决策记录）

| # | 决策 | 理由 | 回滚方式 |
|---|---|---|---|
| ADR-1 | M0 阶段先建立 `src-tauri/` 为纯 Rust crate（不带 Tauri 依赖），M0 三个 Spike 直接在该 crate 内以生产模块形态实现（engine/db/error/paths），S1 再引入 Tauri 依赖与前端骨架 | Spike 代码即未来生产代码，避免一次性 Spike 仓库再迁移；设计 §3.2 模块布局从第一天保持一致 | 无需回滚：S1 在现有 crate 上追加 tauri 依赖即可 |
| ADR-2 | M0 期间不下载 Tauri / 前端依赖；Spike B2 的「事件到前端」以 `LogSink` trait + 测试消费者验证 30ms 分批语义，Tauri emit 实装归 S7 | 保持 M0 最小依赖面，缩短构建时间；管道协议与消费端解耦不影响契约 | S7 换 LogSink 实现即可 |
| ADR-3 | 外部模式唤起弃用 `std::process::Command`，落 `engine::spawn`（Windows `CreateProcessW` 直启 + MSVCRT 引号组装；Unix std）。依据：std 总传父 stdio，keep-open 交互 shell 会 EOF 退出（Spike A 探针实机证据） | 这是 keep-open 正确性的根因级修复；与设计 §5.3.4「短持句柄、fire-and-forget」语义一致，不改变 IPC 契约 | 若后续 Tauri/std 提供等效 stdio 剥离，可换回统一实现 |
| ADR-4 | pwsh 外部 keep-open 采用「`-File` 脚本文件（写数据目录 tmp，启动清扫）」而非 `-NoExit -Command` / 嵌套 pwsh：前者零转义、`exit` 存活（实机 T5/T8）；后两者一个被 `exit` 杀死（T1/T2/T7）、一个需要二次解析（违反 INV-6） | 脚本文件是唯一同时满足 A4 + INV-6 的形态；文件生命周期由 `sweep_script_dir` 收口 | 若嫌文件形态重，可改 `--%` 嵌套（有 %VAR% 漂移风险），属设计文档修订项 |
| ADR-5 | rusqlite pin 0.40.2（设计文档 §4.6 写 0.41.1）：rusqlite_migration 2.6.0 依赖 rusqlite ^0.40，两者不能共存——设计版本表内部矛盾，取「DR-2 两个 crate 都保留」的最小改动 | DR-2 的核心是 rusqlite(bundled)+rusqlite_migration 组合本身，minor 版本不影响任何设计承诺 | 迁移库发新版支持 0.41 时升回并同步设计文档 |
