01

参考调研：这五个产品的语言被拆成了什么

你指定的 magpie 与 ElegantClipboard 提供了「气质基准」，另外补了三个同场景的参照系（Raycast 的启动器交互、 Windows 11 Fluent 的系统材质规范、Linear 的信息密度）。下表只提取可落成设计变量的结论，不做风格拼贴。

magpieyetone · 菜单栏
  • 浅色近白画布 + 单块大白卡，卡内用 1px 细线分隔行，不靠阴影分层
  • 顶部是文字型 tab，当前项用胶囊底色标记；右侧只留极小的图标动作
  • 行结构：图标块 / 名称+状态（绿点+灰字）/ 右侧元信息 / 浅灰下拉 / 开关
  • 字号偏小（11–13px），大量留白由行高和间距制造，而非大标题
取顶部 pill 导航、单卡分组行、绿点状态语言
ElegantClipboardTauri · Win 原生
  • 窗口级 Mica/Acrylic 底材，内容区浮一层白卡，边缘 12px 圆角
  • 左侧导航栏，选中项用深色实底填充，非选中项只有图标+灰字
  • 跟随系统强调色（墨绿/青/黑白）；开关、路径、列表都走 Fluent 语汇
  • 设置页每个分区是一张白卡：标题+一句说明+右侧控件
取白卡浮于画布、分区卡片式设置页、强调色只做「选中态」
Raycast启动器 · 交互
  • 搜索即界面：输入框固定在顶，列表随打字即时收敛
  • 结果行 = 图标 + 主标题 + 右侧灰色元信息，键盘上下选
  • 底部常驻一条快捷键提示栏，告诉用户「现在能做什么」
  • 动作（Action）永远贴着对象出现，不藏在全局菜单里
取搜索常驻、行内动作、底部快捷提示条
Windows 11 Fluent系统规范
  • Mica 只用于窗口底材，Acrylic 只用于临时浮层（菜单/弹窗）
  • 圆角体系 4 / 8 为主，浮层才用到更大的圆角
  • 控件高度 32px 为主，触控目标 ≥ 40px；边框 1px、弱饱和
  • 强调色仅用于：选中、主按钮、焦点环、状态点
取材质分层纪律：底材可透、内容必须是实面
Linear信息密度
  • 紧凑行高 + 极轻分隔线，让 30 条记录一屏可扫
  • 元信息全部降一级：小字号、灰、monospace
  • 状态用小色点 + 文字，不用大色块徽章
  • 空状态写「下一步做什么」，不写营销文案
取紧凑行、元信息降级、状态点、务实的空状态文案

我们要刻意避开的「AI 味」反模式

紫蓝渐变按钮 玻璃拟态 + 大光晕 渐变文字标题 20px+ 全站大圆角 彩色图标塔 数据大屏式装饰图表 三栏等距卡片瀑布 emoji 当图标

这是一款「低频、但每次都要快」的工具（预计每周 3–10 次）。视觉上任何一次炫技都会拉长用户从「想起项目」到「按下运行」的时间。

02

风格方向：三个候选，已选定 C

三个候选的差异只在「骨架」和「材质」，配色/字号/圆角的细节变量是三套共用的。初版提案推荐 A：静默 Fluent， 评审时你确定为 C：纸感暖白 + 橡果棕 + 左侧栏，理由主要是辨识度与松鼠命名的叙事更贴。 因此第 03 节的设计变量与第二阶段的全部原型，都已换成 C 的取值；A / B 保留在这里作为历史对照。

决策记录 · v0.2 风格 C · 纸感暖白 · 框架 左侧栏 · 强调色 橡果棕 #9C5A32。C 本身的「暖色偏软」风险， 通过压低饱和度（#9C5A32 而非橙棕）、只把暖色用于选中态/主按钮/运行点来对冲。
A · 静默 Fluent原推荐 · 未采用

近中性灰画布上铺白卡；顶部工具条 pill 导航；墨绿只出现在选中态、主按钮、运行状态点。行内元信息用等宽字体降级。

读起来像 Windows 自带应用，零学习成本；卡片网格可容纳 12–30 个项目不显吵
品牌性格弱，需要靠一颗松鼠标和空状态插画补一点温度
B · 石墨深色优先备选

深灰画布 + 深色卡，强调色提亮为薄荷绿；整体更接近 Raycast / 终端生态，夜间与 IDE 并置更协调。

「类终端工具」气质强，长时间盯屏更舒服
浅色印刷/演示截图对比度差；Windows 用户默认浅色，首日观感偏「游戏工具」
C · 纸感暖白已采用

暖白纸面 + 橡果棕主色，圆角更大、更像「手帐/笔记本」应用；与松鼠命名的叙事最贴。

辨识度高；暖白底比纯白长时间使用更柔和，截图为社交传播加分
与 magpie / ElegantClipboard 的冷静感偏离；暖色需靠低饱和与「只用于状态」克制

无论选哪套，都遵守的五条骨架规则invariants

① 一屏只有一个主按钮。「添加根目录 / 运行」这类动作永远只有一个实心强调色按钮，其余全部为线框按钮。
② 卡片不叠卡片。内容分层最多两级：画布 → 卡片。详情页里的「命令列表」是行不是卡。
③ 阴影只给浮层。卡片一律 1px 边框；只有弹窗/下拉/抽屉允许投影。
④ 元信息降级。路径、命令原文、次数、时间一律 10–10.5px 等宽灰字，绝不与项目名同字号竞争。
⑤ 颜色即状态。绿=运行/成功，红=失败，琥珀=需注意，橡果棕=可交互。除此之外不用彩色。

交互与响应式约定

这些约定会在原型里真实生效（可点、可键盘操作、可缩放窗口），而不是静态截图。

交互interaction
· 搜索 150ms debounce，Ctrl/Cmd + K 聚焦；Esc 清空并回到网格。
· 卡片命令 chip：单击直接运行；+n 打开小菜单（最多 5 条，更多进详情页）。
· 详情页命令行：悬停显示全部动作；运行中的行「停止」常驻显示。
· 临时命令：可输入、可保存、可运行；保存时必须填名称（弹一层轻量对话框）。
· 折叠区：aria-expanded + 高度过渡 160ms，折叠状态写入 localStorage。
· 所有焦点态用 1px 橡果棕描边 + 4px 浅环（不用 outline:none），键盘可走完所有主流程。
响应式（最终实现）breakpoints
· ≥1140：左栏 216px 完整（导航文字 + 根目录 + 活动会话 + 主题开关），卡片网格 3–4 列。
· ≤1140：左栏收成 60px 图标栏（保留图标与运行点，文字隐藏，悬停给 title）卡片 2 列。
· ≤820：左栏变抽屉 + 顶栏汉堡按钮 + 遮罩；顶栏动作收进页面内，详情页上下堆叠，命令行隐藏时间列。
· 纵向：主内容区独立滚动，详情页日志面板 sticky 贴底；流程页右侧「舞台」同样 sticky。
· 断点值全部来自实测的可用宽度，不是设备宽度猜测；窗口从 1440 拖到 480 全程无横向溢出。
